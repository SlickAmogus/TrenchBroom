# Research: pcport-loading-shared-data

## Summary

The PC port reads ALL game assets at runtime from the original raw 2352-byte-sector .BIN disc image (resolved in main_pc.c, read via PsyCross's CD emulation in pc_port/PsyCross/src/psx/libcd.c); disc_extract/ is dev-time reference only. Files are addressed by a 2074-entry file table (s_FileInfo: 19-bit startSector, 12-bit blockCount in 256-byte units, 6-bit-packed 8-char name, 4-bit path/type indices) compiled into the exe from src/main/filetable.c.USA.inc, indexed by FILE_* enums and by name+type searches. Map geometry (IPD cells, chunk TIMs, global PLM) stays on disc and is streamed through the Fs_Queue state machine; the map DLL contains only game logic and script-like data (events, spawn points, cameras, anim tables, messages). A loose-file override ALREADY EXISTS at the single choke point Fs_QueueTickRead (src/main/fsqueue_3.c:227-383, config key allow_loose_files, path gamedata/load/{FOLDER}/{NAME}.{EXT}), including a hi-res TIM path; its main limitation for an editor is that oversized replacement files can't be byte-replaced because buffer sizes come from the compiled-in file table, and new files (new IPD cells) can't be introduced without regenerating the file table and rebuilding the exe. IPD cell namespaces are shared across map overlays by 3-char tag (notably "ER" is shared by 11 different overlay maps), so editing a shared-tag cell or a _GLB.PLM affects every overlay using that tag.

# Silent Hill PC Port — Runtime Map-Data Loading Pipeline & Shared-Data Map

## 1. File access path: BIN disc image, via file table (disc_extract is NOT a runtime path)

**Runtime source of truth = the original raw `.bin` disc image** (MODE2/2352). `disc_extract/` is used only at build/dev time (e.g. anim-info extraction comments in `pc_port/src/*_anim_infos.c`, and `pc_port/maps/CMakeLists.txt:53-58` compiling `build_gen/extracted_data/<map>_extracted_data.c` generated by `pc_port/tools/extract_map_data.py` from `disc_extract/VIN/MAP*.BIN`).

### Disc resolution and mounting
- `pc_port/src/main_pc.c:327-400` `PcPort_GetGameDiscPath()` — searches `<gamedata>/` for `Silent Hill (USA).bin` / PAL names, else autodetects any `.bin` by reading the ISO9660 PVD at LBA 16 (`fseek(16*2352+24)`, `main_pc.c:288-322`) and root-dir boot serial (SLUS/SLES). Selects the region file table via `Fs_InitFileTableForRegion()`.
- `pc_port/src/main_pc.c:828-836` — passes the path to `PsyX_CDFS_Init(cdImagePath, 0, 0)`.
- `pc_port/PsyCross/src/psx/libcd.c:126-137` `PsyX_CDFS_Init` stores the filename; `libcd.c:639-678` `OpenBinaryImageFile()` fopen's it (called from `CdInit`, `libcd.c:790-810`).

### Sector math (BIN-based)
- Sector size `g_cdSectorSize = CD_SECTOR_SIZE_MODE2 = 2352` (`libcd.c:111`, `PsyCross/src/iso9660.h:60`).
- `CdIntToPos(i)` adds the 150-sector (2 s) pregap and BCD-encodes MM:SS:FF (`libcd.c:320-328`); `CdPosToInt` reverses it (`libcd.c:503-506`). Net effect: file-table `startSector` (an LBA) maps to byte offset `startSector * 2352` in the BIN.
- `CdControl(CdlSetloc)` = `vfseek(&g_imageFile, CdPosToInt(cd)*2352)` (`libcd.c:347-349`).
- `CdRead(sectors, buf, mode)` just queues a command (`libcd.c:508-532`); `CdReadSync` (`libcd.c:534-583`) performs the actual reads: one `vfread` of a raw 2352-byte `Sector` struct per sector, then `memcpy(dst, sector.data, 2048)` — `Sector` layout is sync(12)+addr(3)+mode(1)+subheader(8)+**data(2048)**+EDC/ECC (`iso9660.h:78-86`), i.e. payload begins at raw offset 24.

### The game-side read pipeline (Fs_Queue)
Everything asset-related funnels through the FS queue (`src/main/fsqueue_1.c`, `_2.c`, `_3.c`):
1. `Fs_QueueStartRead(fileIdx, dest)` / `Fs_QueueStartReadTim(fileIdx, dest, image)` / `Fs_QueueStartReadAnm(...)` → `Fs_QueueEnqueue` (`fsqueue_1.c:105-190`) stores `entry->info = &g_FileTable[fileIdx]` (line 177).
2. `Fs_QueueUpdate` (`fsqueue_1.c:227-324`) ticks read state machine `Fs_QueueUpdateRead` (`fsqueue_2.c:8-109`): Allocate → Check → SetLoc → Read → Sync.
3. `Fs_QueueTickSetLoc` (`fsqueue_3.c:138-159`): `CdIntToPos(entry->info->startSector)` + `CdControl(CdlSetloc)`.
4. `Fs_QueueTickRead` (`fsqueue_3.c:214-386`): `sectorCount = (blockCount*256 + 2047)`, then `CdRead(sectorCount >> 11, entry->data, CdlModeSpeed)` (line 385). **Each queued file is read whole in one CdRead — there is no multi-chunk streaming inside the queue.**
5. Post-load: `Fs_QueueUpdatePostLoad` (`fsqueue_3.c:462-515`) → `Fs_QueuePostLoadTim` (`fsqueue_3.c:517-674`, parses TIM, `LoadImage`s pixels+CLUT into VRAM at the caller-supplied `s_FsImageDesc` rect or the TIM's own rect) or `Fs_QueuePostLoadAnm` (`fsqueue_3.c:676-680`).
On PC all reads are synchronous (`Fs_QueueChunksLoad` drains inline, `fsqueue_1.c:33-51`).

### Paths that BYPASS the FS queue (loose override does NOT cover these)
- **XA voice/music streaming**: `pc_port/src/xa_player.c:63-83` opens the BIN itself (`PcPort_GetGameDiscPath`); reads at `(baseSector + currentSector)*2352 + 16` where baseSector comes from `g_FileXaLoc[]` (`xa_player.c:110-117`; region tables at `src/main/fileinfo.c:41-49`).
- **FMV**: `pc_port/src/fmv/fmv_player.cpp:55-70` has a hardcoded FMV table of `base_sector`/`n_sectors` (copied from file-table entries 2044-2073) and demuxes STR sectors straight from the BIN.
- **BGM/SFX (VAB/KDT)**: `src/bodyprog/sound/sd_call.c:1448-1460, 1683-1693` seek by **absolute disc sector** from a parallel, US-baked table `g_AudioData[].fileOffset_8` (region-remapped at `fileinfo.c:95-110`), then `CdRead` into fixed buffers.
- `pc_port/src/fs_pc.c` (`FsPC_ReadFile` etc.) is a dead/unused generic layer — nothing calls it.

## 2. filetable.c.inc / fileenum.h.inc

- The copies at `C:/Claude/silenthill/disc_extract/` root are **byte-identical (modulo CRLF and header comment) to the repo's compiled-in versions**: `src/main/filetable.c.USA.inc` and `include/main/fileenum.h.USA.inc`. Generated by the decomp tool `silentassets` (per notes at `include/main/fileinfo.h:14, 75`); the PAL table was reproduced by `pc_port/tools/gen_pal_filetable.py`. The README/USAGE.md at disc_extract root are unrelated vgmstream docs.
- `filetable.c.inc`: 2074 entries of `s_FileInfo` (`include/main/fileinfo.h:55-64`):
  - `startSector:19` — CD LBA where file starts,
  - `blockCount:12` — size in 0x100-byte blocks (`FS_BLOCK_SIZE`, fileinfo.h:6) → max file size ≈ 1 MB; `Fs_GetFileSize = blockCount*256` (`fileinfo.c:212-215`),
  - `pathIdx:4` → `g_FilePaths[11]` (`\1ST\ \ANIM\ \BG\ \CHARA\ \ITEM\ \MISC\ \SND\ \TEST\ \TIM\ \VIN\ \XA\`, `fileinfo.c:124-136`),
  - `name0123/name4567:24+24` — 8 chars, 6 bits each, ASCII range [0x20,0x5F] (encode/decode: `fileinfo.c:217-308`),
  - `type:4` → `g_FileExts[12]` (`TIM VAB BIN DMS ANM PLM IPD ILM TMD DAT KDT CMP`, `fileinfo.c:138-151`).
- `fileenum.h.inc`: `FILE_<DIR>_<NAME>_<EXT> = index` enums, `FS_FILE_COUNT = 2074` (`fileinfo.h:16-24`).
- **Indexing at runtime is threefold**: (a) direct `FILE_*` enum index (most loads), (b) **enum arithmetic** — `FILE_VIN_MAP0_S00_BIN + mapIdx` (`src/bodyprog/game_boot/game_boot.c:160`) and `FILE_ANIM_HB_M0S00_ANM + mapIdx` (`src/bodyprog/player_control.c:10425-10433`) require the VIN/HB_M runs to remain contiguous and in map order (verified contiguous: enum 1995-2039 for VIN, 60-102 for HB anims), (c) **name+type search** — `Fs_FindNextFile` (`fileinfo.c:344-370`), used for the IPD grid and material TIMs (below).
- PC region handling: both US and EUR tables are compiled in; `g_FileTable` is the active copy in US-canonical index order, with EUR sectors/sizes patched in per same-name match (`src/main/fileinfo.c:19-111`).

## 3. Map DLLs vs on-disc data

### What's in a map DLL (built from `src/maps/<map>/*.c`, see `pc_port/maps/CMakeLists.txt:36-120`; exports `g_MapOverlayHeader_<map>`)
Loaded by `MapRegistry_Load` → `MapOverlay_Load` (`pc_port/src/map_registry.c:215-252`, `pc_port/src/map_overlay_loader.c:28-105`, DLL path `maps/<map>.dll`; raw 0x800xxxxx PSX pointers in the header are nulled at load, `map_overlay_loader.c:82-100`). Contents (example `src/maps/map0_s00/`):
- `s_MapOverlayHdr` (`include/bodyprog/map/map.h:403-...`): pointer to shared `MAP_INFOS[MapType]`, bgm/ambient indices, weather/tint fields, and ~60 function/data pointers.
- **Game-logic data**: `MAP_EVENTS` (`map0_s00_events_data.c` — trigger volumes/scripts), `MAP_POINTS` (`map_points.h` — spawn/warp points, world coords), `mapRoomIdxGet` (per-map hardcoded room-rectangle → room-index function), map messages, `LOADABLE_INVENTORY_ITEMS`, blood splats, world-object init/update code, per-map NPC logic (`Chara_*.c`), camera road data (`vc_road_data.h`), Harry per-map anim-info table (`map0_s00_anim_info.c`), plus build-time-extracted cutscene data (voice cmds/timers/camera waypoints) from the VIN BINs.
- `map0_s00` is statically linked into the exe as fallback; others are stubs if no DLL (`map_registry.c:144-196`).

### What stays on disc (streamed at runtime)
- **`BG/<TAG><XX><ZZ>.IPD`** — one geometry+collision chunk per world cell. TAG = 2-3 char map-type tag; XX/ZZ = signed hex cell coords (`ConvertHexToS8`, `src/bodyprog/gfx/bodyprog_80040B74.c:897-940`). 493 IPDs total. Grid range: x ∈ [-8,7], z ∈ [-8,10] (`Map_MakeIpdGrid`, `bodyprog_80040B74.c:846-895`).
- **`BG/<TAG>*.TIM`** — chunk textures, streamed on demand by material name.
- **`BG/<TAG>_GLB.PLM`** — the map-type's shared model library (global LM), loaded once per map via `mapInfo->plmFileIdx`.
- **`VIN/MAPx_Syy.BIN`** — the PSX code overlay. **Still read on PC** (`game_boot.c:160` into `g_OvlDynamic`) and still load-bearing: `player_control.c:10444-10469` reads PSX header field 0x3C out of the raw overlay to repoint `field_38` (per-map keyframe table) for the 36 maps whose DLLs don't define it.
- `ANIM/*.DMS`/`*.ANM` (cutscenes/animation), `TIM/*` (global/UI/effect textures), `CHARA/*.ILM+TIM`, `ITEM/*`, `SND/*.VAB/.KDT`, `XA/*`.

### The load chain for map geometry
1. `Ipd_PlayerChunkInit` (`src/bodyprog/gfx/world_draw.c:178-241`) reads `mapHdr->mapInfo` → `Ipd_MapFileInfoSet(mapInfo->tag, mapInfo->plmFileIdx, activeIpdCount, isInterior, 0, 0)`.
2. `Ipd_MapFileInfoSet` (`bodyprog_80040B74.c:668-724`) sets `g_Map.mapTag`, queues the global PLM, and calls `Map_MakeIpdGrid` (`:846-895`): **scans the entire `g_FileTable` for `FileType_Ipd` entries whose decoded name starts with the tag, and places each file index into the 16×19 cell grid by the coords parsed from its filename.** This is the only map-geometry "table" — it is derived at runtime from the file table, not stored in the DLL.
3. Chunk streaming: `Ipd_LoadStart` (`bodyprog_80040B74.c:1904-1919`) → `Fs_QueueStartRead(fileIdx, chunk->ipdHdr)` into a slice of the fixed chunk buffer (`Map_Init(GLOBAL_LM_BUFFER, IPD_BUFFER, 0x2C000)`, `world_draw.c:117`; PSX-RAM addresses `include/main/fsqueue.h:37-38`; sliced per original active count — interiors 2 slices of 90112 B, exteriors 4 of 45056 B, PC extra residency slots get 90112 B callocs, `bodyprog_80040B74.c:726-844`).
4. After load, PC reformats the PSX 32-bit binary in place: `IpdHeader_FixOffsets` → `IpdHeader_FixOffsets_PC` (`bodyprog_80040B74.c:2165-2233`, `pc_port/src/ipd_reformat.c:265-390`; validates magic byte 0x14, parses model infos/buffers/collision) and `LmHeader_FixOffsets_PC` (`pc_port/src/lm_reformat.c`).
5. Textures: each material's 8-char name + ".TIM" (`Material_TimFileNameGet`, `src/bodyprog/gfx/bodyprog_80055028.c:4169-4185`) → `Fs_FindNextFile(name, FileType_Tim, startIdx=0)` → `Fs_QueueStartReadTim` into `FS_BUFFER_9` with a VRAM rect from the fixed full/half-page texture slot pool (`Texture_Get`, `bodyprog_80055028.c:4111-4145`; slot rects from `Ipd_TexturesInit`). Because search starts at index 0 and the table is ordered 1ST→ANIM→BG→..., BG TIMs shadow same-named TIM-dir files.

### What a map compiler must keep consistent
- **File table** (compiled into the exe): if the BIN layout changes, `startSector`/`blockCount` for every moved file must be regenerated (`filetable.c.*.inc`) and the exe rebuilt. Growing any file shifts everything after it. Enum order must not change (enum arithmetic on VIN/HB_M runs; `FILE_*` constants used everywhere).
- **IPD internal consistency**: filename cell coords must match header bytes raw[2]/raw[3] (cellX/cellZ); collision block (308 bytes at 0x54) must be regenerated to match geometry; internal offsets (lmHdr at 0x04, modelInfo 0x14, modelBuffers 0x18, modelOrderList 0x50) per `ipd_reformat.c:19-27`.
- **Size ceilings**: IPD ≤ its chunk-buffer slice (90112 B interior / 45056 B exterior); any file ≤ 4095×256 B (12-bit blockCount).
- **External references by name**: material TIM names must resolve via `Fs_FindNextFile`; IPD `modelInfo` entries with `isGlobalPlm` reference models in the tag's `_GLB.PLM` by 8-char name (`ipd_reformat.c:48-55`, resolved by `Ipd_HeaderModelLinkObjectLists`).
- **DLL-side data tied to geometry**: trigger volumes (`MAP_EVENTS`), spawn points (`MAP_POINTS`), room-index rectangles (`mapRoomIdxGet`), camera road data — all world-coordinate data in the DLL must be re-authored when geometry moves (see `pc_port/docs/trigger_zones.md`).

## 4. Shared data across maps

- **`g_FileTable` + `g_FilePaths` + `g_FileExts`** — global, compiled into exe (`src/main/fileinfo.c`).
- **`MAP_INFOS[MapType_Count]`** (`src/bodyprog/sys/map_info.c:468-485`) — in the main exe, NOT per-DLL. 17 map types; each row = {plmFileIdx, tag, chunk-count/interior flags, water zones, speed zones}.
- **IPD tag namespaces are shared across overlays.** Overlay→type mapping (from `pc_port/src/map_registry.c:144-196`):
  - `THR`: map0_s00, map0_s01, map2_s00, map2_s03 — one shared exterior grid.
  - `ER` (**two MAP_INFOS rows, ER and "ER2", both tag "ER"** — `map_info.c:478-479, 484`): map0_s02, map2_s01, map2_s04, map4_s01, map5_s02, map5_s03, map6_s01, map7_s00, map7_s01, map7_s02, map7_s03 — **11 overlays share the ER cell namespace**; each building/final area lives in different cells of the same grid.
  - `SC`: map1_s00/s01/s06; `SU`: map1_s02-s05; `SPR`: map2_s02, map4_s00, map4_s06; `SPU`: map4_s02/s03/s05; `HP`: map3_s00/s01/s06; `HU`: map3_s02-s05 + map4_s04; `DR`: map5_s00; `DRU`: map6_s03; `RSR`: map5_s01; `RSU`: map6_s00/s02; `APU`: map6_s04/s05.
  - **Consequence: an editor touching one "map" may actually touch a grid shared by many overlays.** Editing `ER****.IPD` or `ER_GLB`-referenced textures can affect all 11 ER overlays.
- **`BG/<TAG>_GLB.PLM`** — shared by every cell and every overlay of that tag.
- **TIMs are shared by name**: any IPD/PLM material naming the same TIM shares it; the streamed slot pool (8 full-page + 2 half-page slots) is global (`bodyprog_80040B74.c:600-625`).
- **Truly global assets** (any map may load them): `TIM/` effect/UI textures (e.g. `FILE_TIM_BLD_TIM` blood, per-map effect TIM sets in `Map_EffectTexturesLoad`, `src/bodyprog/bodyprog_8005E0DC.c:43-102`), `CHARA/` (Harry + all NPC models/anims via `CHARA_FILE_INFOS`), `ITEM/`, `ANIM/HB_*` weapon/player anims, `SND/` VAB/KDT (absolute-sector table), `1ST/` boot files.
- **Is a map's IPD self-contained?** Geometry, model instances, draw order, and collision: yes (all inside the IPD). Not self-contained: textures (external TIMs by name), global-PLM model references (by name), the cell position (from its own filename), and all gameplay data (triggers/spawns/cameras/rooms) which live in the map DLL/VIN overlay. So an editor that only rewrites one cell's IPD + its uniquely-named TIMs cannot corrupt other maps **unless** the tag/TIM/PLM is shared (see above) or the file table is perturbed.

## 5. Loose-file override — ALREADY IMPLEMENTED, plus gaps

**The choke point the task asks for already exists** and is exactly where predicted: `Fs_QueueTickRead` at `src/main/fsqueue_3.c:227-383` (SH_PC_PORT block), gated by config `allow_loose_files` (`pc_port/src/pc_config.c:23, 309-311`; documented in `pc_port/config.cfg:129-135`).
- Probe path: `gamedata/load/{FOLDER}/{NAME}.{EXT}` built from `g_FilePaths[file->pathIdx]` + `Fs_GetFileInfoName` (`fsqueue_3.c:262-282`), e.g. `gamedata/load/BG/ER_AQSH1.TIM`, `gamedata/load/BG/THR0000.IPD`.
- Hit ≤ buffer size: `fread` straight into `entry->data` and `return true`, skipping `CdRead` entirely (`fsqueue_3.c:289-357`). Works for **any** file type routed through the FS queue (IPD, TIM, PLM, ANM, DMS, TMD, VIN BIN...), since every queue read is a whole file.
- Hit > buffer size: treated as a **hi-res TIM**: stashed in a pending table (`fsqueue_3.c:161-212`), disc TIM still read, then `Fs_QueuePostLoadTim` registers a GL texture override keyed by the VRAM rect (`fsqueue_3.c:596-670` → `HiresOverride_RegisterFromTim`, `pc_port/src/hires_override.c`).
- Miss: falls through to `CdRead` (`fsqueue_3.c:385`).

### Complications / caveats for editor use
1. **Buffer size comes from the compiled-in file table**, not the loose file: `bufSize = ALIGN(blockCount*256, 2048)` (`fsqueue_3.c:292`; also `Fs_QueueAllocEntryData` at `fsqueue_3.c:52` and overlap math at `fsqueue_3.c:100-103`). A replacement IPD/PLM **larger than the original's table size cannot be byte-replaced** — it is misrouted into the TIM hi-res path. Practical rule for an editor today: emit files ≤ the original file's sector-aligned size, or regenerate `filetable.c.USA.inc` + rebuild. (Even with a bigger table size, IPDs are hard-capped by the chunk slot: 90112 B interior / 45056 B exterior slice.)
2. **Oversized non-TIM loose files leak stale `HiresPending` entries**: the pending table is keyed by queue-entry pointer and popped only in `Fs_QueuePostLoadTim`; a plain read (postLoad=None) never pops, and queue entries are recycled (32-slot ring, `fsqueue.h:8`), so a later TIM read reusing the same entry address could pop the wrong path (`fsqueue_3.c:177-211`). Avoid oversized loose files for non-TIM types.
3. **No new files / new cells**: the IPD grid is built only from `g_FileTable` (`Map_MakeIpdGrid`), and the loose probe only fires for files already enqueued by index. Adding a brand-new cell (new `TAGxxzz.IPD` name) requires appending a file-table entry + enum and rebuilding the exe (sector can be fake if a loose file always exists — the loose hit returns before CdRead — but `blockCount` must still be set for the buffer size). A cleaner editor-support extension would be to also scan `gamedata/load/BG/` for extra `<tag>xxzz.IPD` names inside `Map_MakeIpdGrid`'s SH_PC_PORT block.
4. **Loose path is CWD-relative** (`"gamedata/load/%s/%s"`, `fsqueue_3.c:281`), ignoring the `-data` override that `g_GameDataPath` honors (`main_pc.c:270-278, 416-419`) — the game must be launched with CWD at the install/build dir.
5. **Not covered by the override**: XA audio, FMV, and BGM/SFX VAB/KDT loads (all bypass the FS queue and read the BIN by absolute sector — see §1). Map/geometry editing is unaffected by this.
6. TIM byte-replacement of the **same dimensions/bpp** is clean (the engine re-uploads to the same VRAM rect); dimension changes should go through the hi-res path (same aspect, scaled) or will corrupt VRAM neighbors.
7. Per-file cost is one `fopen` probe; `SH_LOOSE_VERBOSE=1` env var logs every miss (`fsqueue_3.c:247-258`).

### Editor test loop (works today)
Set `allow_loose_files = 1` in `config.cfg`, write edited files to `gamedata/load/BG/<NAME>.IPD` / `<NAME>.TIM` (size ≤ original sector-aligned size), relaunch the game (or re-enter the map — chunks are re-read from the queue on map re-entry). No disc rebuild needed.

## Open questions

- Whether Map_MakeIpdGrid should be extended (SH_PC_PORT block) to scan gamedata/load/BG/ for IPD names absent from g_FileTable — currently new cells cannot be added without regenerating filetable.c.USA.inc + fileenum.h.USA.inc and rebuilding the exe; this is the main missing piece for a level editor that adds geometry rather than replacing it.
- Exact hard size ceiling for edited interior IPDs: the 90112-byte slot slice is the cap for byte-replacement, but whether any retail interior IPD already approaches it (largest observed blockCount) was not measured; an editor should validate output size against both the file-table size and the slot slice.
- The stale HiresPending entry leak for oversized non-TIM loose files (fsqueue_3.c:161-212) is a latent bug worth fixing before editors routinely produce oversized files.
